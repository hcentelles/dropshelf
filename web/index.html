Complete any sign-in or access approval when prompted. You can also use the manual steps below.

    Sign in with Cloudflare Access

    Start OAuth sign-in from your MCP client. In the browser, enter an email address that has access to this instance. Enter the email code, then select Allow to approve the connection.

    Call whoami, then list_files on this MCP server.

    The identity should show your approved email address. File links require Cloudflare Access sign-in too.

Available tools

whoami
Check your upload identity.
list_files
Search by file name and filter by type or author.
get_file_filters
Get file types and authors.
get_file
Get file and download links.
create_upload
Start a file or folder upload.
check_uploads
Check existing paths before replacement approval.
upload_file
Upload text or binary files.
trash_file
Move a file to Trash.
restore_file
Restore the original file link.
delete_file_permanently
Delete a file from Trash after confirmation.

Use trash_files, restore_files, or delete_files_permanently for up to 10 files per call.

Use list_files with view: "trash" to list Trash. Permanent deletion requires confirm: true.

For a folder, call create_upload once. Reuse its uploadId and keep each relative path so HTML can load its images.

Folders with the same full path merge. Before replacing a file, call check_uploads, ask for approval, then pass the file ID and version in upload_file.replace. The file link stays the same.

For larger files, use the web app or ask create_upload for an HTTP upload URL. HTTP requests must use the same Access OAuth token.

Connection help
  • If sign-in is blocked, ask the instance administrator to approve your email address.
  • If your session has ended, sign in again from your MCP client.
  • If sign-in does not start, check that your client supports Streamable HTTP and OAuth resource indicators (RFC 8707).
  • If tools do not appear after setup, reload the MCP connection or start a new chat.
Agents without a browser

An administrator must enable Cloudflare Access service-token authentication and configure an agent display label first.

Store the client ID and secret in the agent's secret store. Configure the client to send these headers:

CF-Access-Client-Id: YOUR_SERVICE_CLIENT_ID
CF-Access-Client-Secret: YOUR_SERVICE_CLIENT_SECRET

These uploads show the configured agent label. They have no uploader email.
